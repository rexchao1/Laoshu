# Laoshu

A personal iPhone app for learning HSK Chinese vocabulary by swiping through graded daily sessions. Offline, one user, no account. Every rule lives in the Swift package `LaoshuKit/`; the SwiftUI app in `Laoshu/` is a thin shell over it.

## Commands

| Command | What it does | Needs |
|---|---|---|
| `scripts/check` | Import boundaries, kit tests, gloss rules, measurements, database shape. About 10 s warm. | swift, python3, sqlite3 |
| `scripts/test` | Kit tests alone. `scripts/test --filter StreakTests` narrows. | swift |
| `scripts/build` | Compiles the app for the simulator. Minutes cold, seconds warm. | Xcode |
| `scripts/run` | Builds, boots a simulator, installs and launches. `--reset` wipes progress. `SIM="iPhone 17e"` picks a device. | Xcode |
| `scripts/screenshot [path]` | Captures the booted simulator to a PNG and prints the path. | a running `scripts/run` |
| `scripts/check-full` | `scripts/check` then `scripts/build`. The release gate. | Xcode |

The catalogue ships inside the app; nothing needs seeding. Progress lives on the simulator until `scripts/run --reset`.

## Architecture

`docs/ARCHITECTURE.md` maps the domains, where each lives, what may import what, and which checks hold the boundaries. Read it before touching anything in `LaoshuKit/`.

The one rule that shapes everything: a rule a test can check lives in `LaoshuKit/`, never in a view. If a change makes a view decide something, move the decision into the kit and test it there.

## Rules

- `LaoshuKit/` imports Foundation, GRDB, and Observation only. No SwiftUI, UIKit, or AVFoundation. `scripts/check-imports` fails otherwise and says where the code should go.
- `Laoshu/` never imports GRDB, and only `SpeechSpeaker.swift` imports AVFoundation. Views read and write through the kit's stores and engine. Same check.
- `data/laoshu.sqlite` is generated, not edited. Rebuild it with the two `laoshu-build-db` commands in `README.md`, then copy it to `Laoshu/laoshu.sqlite`; `scripts/check` fails while the two differ.
- `docs/measurements.md` is generated by `docs/measure.py`; regenerate it, never edit it. `scripts/check` fails while it is stale.
- Glosses in `data/glosses.tsv` follow the rules in `docs/check_glosses.py`, which `CatalogueBuilder` applies again at build time.
- Dates are `LocalDate` strings, `YYYY-MM-DD`, never timestamps. The batch ladder reads the clock only through `TodayProvider`, so tests can move the day.
- Schema changes are a new numbered migration in `LaoshuDatabase.swift`. Existing migrations are never edited.
- The vocabulary and glosses derive from CC-CEDICT under CC BY-SA. `data/ATTRIBUTION.md` says what that requires; keep it true.

## Product constraints

- Hanzi is shown to disambiguate and to drive speech. It is never tested and never asked for.
- No per-word due dates or memory state. A batch moves along one ladder: introduced, next day, seven days later, retired.
- Session state is in memory only. Leaving a session abandons it.
- One user, no accounts, no network, no analytics.

## UI

- `LaoshuTheme.swift` holds every colour and the type scale. New screens use it; nothing defines its own palette.
- A UI change is verified by running it: `scripts/run`, then `scripts/screenshot` before and after, and the report names the simulator used.
- Views render what the kit hands them. A view that branches on a rule is the wrong place for the rule.

## Git

- Work on `main`, direct commits, pushed to `origin` when a change is done and checked.
- Look at the working tree before pulling. Never discard another change to make room for yours.
- Commit message: what changed and why, in plain words. No agent attribution, no session links, no machine names.

## Verify

- A kit change gets a kit test that fails without it, then `scripts/check`.
- A view change gets `scripts/run` and a screenshot. `scripts/check-full` before the commit.
- A copy or layout tweak can ship after reading your own diff and one screenshot.
- Report what ran and what did not. A check that did not run did not pass.

## Where knowledge goes

| What | Where |
|---|---|
| A rule about study, placement, progress, or storage | A test in `LaoshuKit/Tests/`, and a doc comment on the type it constrains |
| Why a checkpoint was decided the way it was | `docs/decisions/checkpoint-NN.md`, one file per checkpoint, never rewritten |
| A boundary or domain change | `docs/ARCHITECTURE.md`, updated in place |
| A new document under `docs/` | Created with the line in `AGENTS.md` that says when to read it, in the same commit. `scripts/check-docs.py` fails on a document nothing points at |
| Work that spans sessions | One file in `docs/plans/active/`, moved to `docs/plans/completed/` with a Result when done |
| A measurement a decision cites | `docs/measure.py`, so it regenerates |
| Ordinary completed work | The commit message |
